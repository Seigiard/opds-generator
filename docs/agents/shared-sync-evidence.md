# Shared synchronization engine final evidence (#64)

This is the final cross-application evidence for the accepted shared synchronization contract in ADR 0004 and issue #49.

OPDS review follow-up supersedes only OPDS's consumed package version: OPDS now uses the reviewed registry release `@seigiard/sync-engine@0.5.5` with lock integrity `sha512-G2Wt1V62P9ciywD4E/2c7l9vjXPzjokQy7c5WWNY8HKFP8hWpKUZr0fZ7M9fNFkVj4a9FVUEIqN2tyA4GZbv0Q==`. Registry `0.5.4` is an older build. TTRPG Map Viewer and OPML Generator remain covered by the #64 `0.5.0` evidence below until their own update.

OPDS `0.5.5` registry equality evidence: the reviewed package was extracted outside the repository; host `node_modules/@seigiard/sync-engine` and production image `/app/node_modules/@seigiard/sync-engine` both diffed cleanly against that extracted package. Archive SHA256 is `4bd09ff578204d3f3ebb8597bef4dd2b85e6ea4d9797291093b9eb109e3d78e6`, from engine commit `1e59877`. Changes over registry `0.5.4`: persistent failed-opening retries are bounded to admitted requests, descendants below a file ancestor observe as absent instead of raising `Source ancestor is not a directory`, freshness stamp and declared-output `ENOTDIR` are treated as absence, request payloads are owned in one holder so a failed one-shot retry keeps its force and hints, every live activity reports exactly one outcome whatever its exit, a failed trailing traversal no longer re-runs an applied request, `enqueue` evaluates keys once and compacts queues in place, later pass resources are released when a pass ends after its handlers stop, reconcile ticks no longer keep a retry cycle alive, live session state is driven by `src/live-machine.ts`, `followUp` is null while a failed session waits, closing-window requests after a failed attempt answer `queued`, fatal failure closes admission at detection, and ticks act only while idle.
